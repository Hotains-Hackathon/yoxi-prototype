# PRD 補足建議

完整的體驗流程、AI、資料治理、成本與驗證安排見[提案正文](../05-delivery/提案正文.md)。此頁是產品規格骨架，細部門檻皆為提案設定。

## MVP 使用流程

1. 使用者從「今日靈感」進入每日更新的活動頁，依日期、城市、距離或主題篩選；第一版以首頁入口測試，推播僅對選擇接收者試驗頻率與時段。
2. 開啟詳情，確認活動時間、地點、來源與交通提示，選擇收藏、分享或前往叫車。
3. 選擇叫車後，App 帶入目的地；使用者仍可確認上車點、車種與價格。
4. 每日登入、到訪公開景點與完成符合規則的訂單分別發放今日碎片、探索印記與路線碎片；使用者完成 6 或 9 片的城市拼圖卡後，可結合頭貼或自選個人符號分享與收藏。只有少量路線碎片或系列完成可能帶有回饋。

本提案以既有 App 可串接活動資料、推播、券、地理圍欄與叫車服務為前提；正式開發前仍須確認介面、權限與失敗降級方式。AI 的資料流程與第一版推薦邏輯見 [AI-方案建議.md](AI-方案建議.md)。

## 功能規格與狀態

| 功能 | 必要資料／狀態 | 例外處理 |
| --- | --- | --- |
| 活動卡 | 名稱、時間、座標、標籤、來源、更新時間、狀態 | 過期或取消時下架並告知已收藏者 |
| 叫車導流 | 活動 ID、目的地、預計抵達時間、歸因 ID | 定位／地址無效時允許手動修正 |
| 城市拼圖卡 | 使用者 ID、卡片主題、6 或 9 片組合、頭貼／個人符號、分享設定 | 頭貼採既有使用者授權範圍；未授權時使用預設符號，分享預設不公開 |
| 碎片取得 | 每日資格、景點印記、訂單狀態、活動歸因、目的地條件、碎片 ID、風險分數 | 每日與每地點有上限；取消、退款、模擬定位或異常訂單不發路線碎片；不支援行進中領取 |
| 驚喜回饋 | 金色碎片／系列完成資格、回饋內容、期限、使用狀態 | 機率、金額與上限待營運核定；庫存不足、過期、重複使用需有明確訊息 |

## MVP 不包含

- 自建售票、完整社群討論區、任意地點自動發獎。
- 以生成式 AI 自行編造活動內容或以黑箱推薦決定所有曝光。
- 未經內容與法務審查的付費活動刊登。

## 驗收標準範例

- 活動詳情按下「前往叫車」時，目的地與活動歸因 ID 正確帶入，且使用者可編輯上車點。
- 每個符合資格的完成訂單最多發放一次碎片；取消訂單不會累積進度，重送請求不會多次發獎，模擬定位與異常跳點會被攔截或進入複核。
- 活動過期、取消、無法定位與網路失敗皆有可理解的畫面與可回復操作。
- 埋點至少涵蓋曝光、點擊、收藏、叫車啟動、訂單完成、碎片發放、拼圖完成、分享、兌換與異常原因。

## 開發前技術決策

確認活動 CMS／資料來源、地圖與地理圍欄、券系統、通知服務、身分／裝置反作弊、事件分析與資料刪除機制。每項整合都要指定資料擁有者、失敗降級方式與監控告警。
