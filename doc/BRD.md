# BRD｜yoxi 今日靈感：活動探索與專屬景點拼圖

> 提案版商業需求文件：說明商業問題、目標、可行性與驗證方式，不作為開發規格或上線承諾。公開資料來源見[來源登錄](05-delivery/sources.md)。

## 產品背景與商業問題

yoxi 的叫車服務通常在使用者已有明確移動需求時才被開啟。企業挑戰題希望找出「不搭車也願意打開 yoxi」的理由，並將互動轉化為真實叫車需求。[題目說明](topic/yoxi.md)

本方案以「今天／週末去哪裡」作為非交易入口。使用者先發現可去的活動，再在決定出發時直接規劃叫車；每天登入、到訪景點與完成符合資格的行程都可累積城市拼圖卡。拼圖與收藏服務回訪，叫車導流則負責驗證商業價值；折價僅是少量路線碎片或系列完成時可能出現的驚喜。

## 目標與範圍

| 項目 | 提案定義 |
| --- | --- |
| 主要目標 | 提高活動內容帶來的增量完成訂單 |
| 次要目標 | 增加活動頁使用、收藏、分享與 7／28 日回訪 |
| 服務範圍 | 全台可瀏覽通過資料品質門檻的活動；上線依城市資料密度與供車能力分批驗證 |
| 目標使用者 | 會搜尋週末或下班後活動、偶爾叫車且有分享習慣的成年人；18–35 歲為訪談招募配額，尚非已驗證客群 |
| 不在範圍 | 自建售票、完整社群平台、任意地點自動發獎、未審核的付費刊登 |

題目提供的去識別行程樣本涵蓋多個城市，因此不把雙北設定為唯一範圍；樣本沒有活動瀏覽、年齡或社群行為，不能把受眾假設寫成已證實事實。[資料分析](01-discovery/topic-資料回答與發現.md)

## 使用者價值與商業轉換

- 使用者在同一處取得活動時間、地點、來源、更新狀態與交通提示，減少跨平台查找與決策摩擦。
- 使用者點選「前往叫車」後，可帶入活動目的地，仍自行確認上車點、車種與價格。
- 每日登入取得今日碎片、到訪景點取得探索印記、完成符合資格的訂單取得路線碎片；使用者可持續完成一張 6 或 9 片的個人化城市拼圖卡。
- 完成卡片的主要回饋是收藏冊、系列徽章與個人化分享圖；少量路線碎片或系列完成才可能帶有搭車金、合作權益或較高折扣。
- yoxi 以活動頁、叫車啟動與完成訂單事件量測轉換；若成效成立，再評估主辦方合作券、贊助活動與匿名彙總成效報告。

分享不直接提供現金或券，避免純流量套利。到訪景點可取得無折扣資格的探索印記，滿足輕鬆探索；只有完成訂單取得的路線碎片才可能連結回饋，保留叫車轉換價值。

## 商業模式、成本與可行性

第一階段的價值是驗證拼圖收藏能否帶來日常回訪與正向的增量訂單。yoxi 官網已有搭車金、優惠券與活動合作案例，故可將少量驚喜回饋作為提案中的既有能力假設；活動資料、訂單歸因及拼圖發放是否可串接，仍須導入前確認。[yoxi 優惠案例](https://www.yoxi.app/promotion/978)

提案不再以「每完成一張卡就送券」作為前提。成本分為兩類：插畫授權與版型製作的固定成本，以及金色路線碎片／系列完成回饋的變動成本。插畫採一張主圖切成 6 或 9 片並套用共用版型，每季先委託 4–6 張主插畫，再依概念測試決定是否擴大。若採 1,000 張 NT$30 的驚喜回饋且 30% 使用，折抵成本為 NT$9,000；這只是一個回饋成本上限示例，並非完成卡片的保證獎勵。

`增量完成訂單 × 單筆貢獻 − 實際驚喜回饋成本 − 插畫授權／資料／AI／人工審核／客服等新增成本`

題目資料僅提供付款區間，沒有單筆貢獻、券兌換率、供車成本或現有 DAU，故不估算 ROI 百分比。技術與營運成本可先以資料擷取與儲存、模型呼叫、地圖路程查詢、人工複核及推播的實際用量填入估算表。

## 成效驗證

主要指標為：28 天內，每 1,000 名符合資格使用者完成的活動相關訂單數，在隨機實驗組與對照組的差值。兩組使用同一套活動地點與期間規則標記訂單，另看全站完成訂單差值，避免只把既有訂單移到活動入口。

| 階段 | 指標 | 護欄 |
| --- | --- | --- |
| 觸及 | 活動卡曝光、詳情點擊、收藏 | 過期／錯誤資訊回報率 |
| 轉換 | 叫車啟動、完成訂單、活動相關訂單增量 | 取消、未派成、客服申訴 |
| 留存 | 7／28 日回訪、每日碎片領取、拼圖完成、分享 | 推播退訂、疑似作弊、插畫與回饋成本 |

## 風險與提案對策

| 風險 | 對策 |
| --- | --- |
| 活動資料過期或不完整 | 優先採官方開放資料；保留來源與更新時間；過期、取消或無法定位時下架 |
| 驚喜回饋只補貼原本會搭的行程 | 以隨機對照看訂單增量與淨貢獻，設定金色碎片機率、每人與每月上限 |
| 活動散場供車不足 | 不承諾一定有車；試點觀察未派成與取消率，調整曝光城市／時段 |
| 定位或多帳號套利 | 探索印記不帶折扣且每地點一次；只有完成訂單的路線碎片可有回饋，取消／退款回收，異常帳號交複核 |
| 使用者不願每日互動 | 以收藏、回訪與叫車增量驗證；若證據不足，不將瀏覽量當成成功 |

## 提案時程與決策點

| 階段 | 時長 | 決策輸出 |
| --- | --- | --- |
| 資料與使用者研究 | 2 週 | 抽樣兩個資料源各 100 筆；完成 12 人訪談 |
| 概念驗證 | 2 週 | 驗證活動清單、叫車入口與拼圖圖卡是否可理解、有吸引力 |
| 可行性與營運評估 | 4–6 週 | 確認活動資料、券、叫車導流、事件追蹤、隱私與客服可否支援 |
| 城市試點 | 4 週 | 產出增量訂單、成本、資訊品質與風險結果，決定是否擴大 |
