# yoxi 今日靈感｜活動探索與專屬景點拼圖

> 簡報生成用提案定稿，依繳交要求整理為七章。這是概念方案，不代表 yoxi 已上線相關功能。文中的時程、成本、獎勵規則、排序權重及研究安排均為提案假設；成效尚未實測。公開來源記錄日期為 2026-09-25，對外使用前應重新確認資料、授權與法規狀態。

## 1. 提案概述

**一句話：**每天打開 yoxi 找到去得成的城市活動；想出發時，直接規劃叫車。

[企業挑戰題](topic/yoxi.md)希望 yoxi 從「有叫車需求才開啟」的工具，變成不搭車時也有持續價值的城市生活夥伴。本案以可信的當日及週末活動作日常入口，串起「活動發現 → 可達性判斷 → 前往叫車」，再以每日、探索及搭車累積的城市拼圖卡支持回訪。

**主要商業目標**是驗證活動內容是否帶來增量完成訂單；活動使用、收藏、分享及 7／28 日回訪為輔助指標。概念上全台可瀏覽符合品質門檻的活動，正式上線城市依活動密度與供車能力分批決定。拼圖完成後以收藏及個人化分享為主要回饋，折扣只作少量驚喜。

## 2. 目標對象與痛點分析

首輪研究對象是會搜尋週末或下班後活動、偶爾叫車且有分享習慣的成年人。18–35 歲是招募配額之一，**不是已證實的核心客群**。題目資料沒有年齡、活動瀏覽、社群分享或訪談紀錄，不能推論使用者會每天開啟 App。[樣本分析](01-discovery/topic-資料回答與發現.md)

| 待驗證痛點 | 方案回應 | 驗證方法 |
| --- | --- | --- |
| 活動資訊分散，難知是否仍有效 | 活動卡列明來源、日期、地點、更新時間及取消狀態 | 訪談最近一次找活動的流程與放棄原因 |
| 決定要去後，仍要查交通、重輸目的地叫車 | 詳情頁顯示已核對的交通資訊與「前往叫車」入口 | 量測詳情至叫車啟動、完成訂單的漏斗 |
| 單次活動後缺少回訪理由 | 每日新活動、收藏狀態與城市拼圖卡 | 量測 7／28 日回訪，測試圖卡收藏與分享意願 |

競賽提供 **964,991 筆有效去識別行程**；熱門下車 POI 分布於台北、台中、桃園、台南及高雄等地。這支持全台構想，但不能證明各地活動需求或推估市場規模。付款資料只有區間，也無法據此推算單筆貢獻。[樣本分析](01-discovery/topic-資料回答與發現.md)

## 3. 解決方案設計

1. 使用者從首頁進入「今日靈感」，依城市、日期、興趣及可達性瀏覽近期活動。卡片列出來源、更新時間、活動日期及售票資訊。
2. 詳情頁呈現已核對的地點、時間、原始來源與交通資訊，可收藏活動。過期、取消或無法定位的活動不曝光，並通知已收藏者。
3. 按「前往叫車」後帶入目的地與活動 ID；使用者仍可修改上車點、車種與目的地，並確認實際價格。供車不足時不承諾一定有車。
4. 每天可選一張當期拼圖卡領取「今日碎片」；抵達公開景點或活動區域、再開啟 App 可領「探索印記」；完成符合資格的 yoxi 訂單可取得「路線碎片」。一張卡由 6 或 9 片構成。
5. 完成後產生城市收藏卡、徽章及可自行分享的圖卡。預設用自選符號個人化；頭貼須取得同意，圖卡預設不公開，分享本身不發券。

**獎勵規則：**探索印記每地點、每期最多一次，不帶折扣資格；一筆合格且未退款的活動目的地訂單最多發一片路線碎片，重送事件須去重。只有少量金色路線碎片或完成系列才可能帶有搭車金、合作權益或較高折扣；機率、額度及總量待營運核定。異常定位、退款及疑似多帳號行為須暫緩或複核。這些是提案規則，並非現有系統能力聲明。[產品需求](PRD.md)

不搭車時仍可看新活動、比較日期及路程、更新收藏。初期以首頁固定入口驗證；推播僅在使用者選擇接收後小規模測試，其時段與頻率依試點結果決定。

## 4. AI 應用方法

**AI 的核心工作是整理公開活動資料並選出適合的內容。**資料起點是文化部[藝文活動資料集](https://opendata.culture.tw/frontsite/openData/detail?datasetId=302)與觀光署[觀光活動資料集](https://data.gov.tw/dataset/7778)。兩個資料集頁面均標示每日更新，但不保證每筆活動完整或即時。[來源登錄](05-delivery/sources.md)

```text
官方活動資料 → 排程擷取 → 來源／授權／時間／地點檢查
             → 去重、座標與狀態驗證 → 活動資料庫
             → 可解釋排序 → yoxi 活動清單與詳情
             → 前往叫車 → 訂單事件與拼圖發放
```

- **資料理解：**完整欄位用程式規則處理；非標準文字才由可輸出 JSON 的中文語言模型抽取，再經 schema 驗證、來源比對與人工抽樣。保留來源 ID、原始網址、授權及取得時間。
- **推薦排序：**第一版依明示興趣／收藏、日期時間、可達性、新鮮度及來源品質做規則排序。概念權重為 35%／25%／20%／10%／10%，須在試點調整；累積足夠事件後再比較學習排序模型。
- **防誤導：**推薦理由只引用核實欄位；AI 不補寫未確認的票價、時間、地點或取消資訊。未登入者依選定城市與日期呈現；登入且同意後，才使用收藏、瀏覽及粗粒度活動區個人化，並提供關閉與刪除選項。
- **治理：**政治、宗教、成人、賭博及高風險活動不作個人化推播；爭議內容下架複核。公開資料標示來源，圖片另核授權；個資告知、利用與刪除流程交法務審核。[開放資料授權](https://data.gov.tw/license)／[個人資料保護法](https://law.pdpc.gov.tw/LawContent.aspx?id=FL010627)

模型、地圖服務、API、運算環境及與既有叫車／券系統的介接方式，須依價格、延遲、權限及現有架構確認。

## 5. 獨特優勢與差異化

ACCUPASS 已提供[活動搜尋](https://www.accupass.com/search)，Klook 提供[景點、活動與交通產品](https://www.klook.com/zh-TW/)，Uber 在台灣提供[即時](https://www.uber.com/tw/zh-tw/ride/ubertaxi/)及[預約叫車](https://www.uber.com/tw/zh-tw/ride/how-it-works/reserve/)。本案不主張活動或叫車功能為市場獨有。

**待驗證的差異化組合：**有來源的當日活動 → 可解釋的出行建議 → 一鍵規劃 yoxi 叫車 → 每日探索與完成訂單累積個人化城市收藏。它把「找活動」與「實際出發」放在同一流程，並以收藏為主、補貼為輔的拼圖機制支持回訪。

yoxi 官網已有[乘客優惠與搭車金](https://www.yoxi.app/passenger)及[活動合作券案例](https://www.yoxi.app/promotion/1039)，可作回饋模式參照；「今日靈感」、拼圖、歸因與資料串接仍屬新提案。若增量訂單成立，後續再評估合作券、明確標示的贊助活動及匿名彙總導流報告。[市場需求](MRD.md)

## 6. 預期效益與落地評估

**主要指標：**28 天內，每 1,000 名符合資格使用者完成的「活動相關訂單數」，比較隨機實驗組與對照組的差值。兩組須用相同的活動地點及期間規則辨識訂單，並檢查全站完成訂單差值，避免把既有行程移到活動入口後誤算為增量。[商業需求](BRD.md)

**輔助漏斗：**活動曝光 → 詳情點擊／收藏 → 叫車啟動 → 完成訂單；另觀察每日碎片、探索印記、路線碎片、拼圖完成、分享及 7／28 日回訪。護欄包括資訊錯誤率、取消／未派成率、客服申訴、推播退訂、疑似作弊率及單筆增量淨貢獻。數據團隊須先依基準量及最小可檢出效果計算樣本數；不足時不宣稱顯著成效。

**成本與損益：**一張主插畫切為 6 或 9 片並共用版型；初步規劃每季委託 4–6 張主插畫，先測試偏好再擴大。成本包含插畫授權／版型、資料與儲存、模型推論、地圖查詢、人工複核、客服及實際使用的驚喜回饋。假設發放 1,000 張 NT$30 回饋、使用率 30%，實際折抵為 **NT$9,000**；這是試算，不代表每張卡保證有獎。損益以「增量完成訂單 × 單筆貢獻 − 回饋折抵 − 插畫／資料／AI／人工等新增成本」估算。現缺單筆貢獻、兌換率及 DAU，不能給可信 ROI 百分比。
